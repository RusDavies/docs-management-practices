# Docs Management Practices

Guidance for managing people, teams, decisions, accountability, and operating cadence across different management levels.

This project is deliberately practical. It is not management theatre, leadership poster filler, or an excuse to create process for its own sake. The goal is to help managers at different levels run healthier teams, make better decisions, and create accountability without turning work into a bureaucracy swamp.

## Core Philosophy

Healthy teams make trust explicit, disagreement safe, decisions clear, commitment real, accountability normal, and results shared.

The guidance leans toward the practical spirit of Patrick Lencioni's team-health model: trust first, productive conflict, commitment, peer accountability, and collective results. It should not become a Lencioni fanzine. Use the ideas because they work; write the guidance in our own voice.

A central doctrine:

> Disagree openly before the decision. Commit honestly after the decision.

## Companion Agent Specialist Layer

Agent-facing management specialist artifacts live in [agent-specialist-registry](https://github.com/RusDavies/agent-specialist-registry/blob/master/README.md), not in this repository.

This repository remains the canonical human-readable management-practices corpus. The agent-specialist repository maps from this corpus, generates or validates specialist task packs, retrieval chunks, evaluation scenarios, and review gates, and checks for drift when the canonical guidance changes.

Do not duplicate agent task packs, eval suites, or behavioral operating guidance here. If the management doctrine changes, update this corpus first; then regenerate, validate, or review the downstream agent-specialist artifacts.

For mapped discipline guidance, preserve stable `<!-- doctrine:id=... -->` source anchors and retrieval-friendly `##` section structure. See [Repository Conventions](https://github.com/RusDavies/docs-management-practices/blob/master/REPOSITORY_CONVENTIONS.md) for the source-anchor and retrieval-structure standard.

## Role Corpus Boundary

This repository is management/leadership-scoped. It should not absorb practitioner/operator role guidance merely because the domain is adjacent.

Use [Role Corpus Architecture](https://github.com/RusDavies/docs-management-practices/blob/master/ROLE_CORPUS_ARCHITECTURE.md) for the split between management roles, practitioner roles, operator roles, hybrid roles, domains, disciplines, and authority boundaries.

Use [Role Scope Split Examples](https://github.com/RusDavies/docs-management-practices/blob/master/ROLE_SCOPE_SPLIT_EXAMPLES.md) for initial software engineering, quality, and HR examples.

Practitioner/operator guidance lives in [docs-practitioner-practices](https://github.com/RusDavies/docs-practitioner-practices), with cross-references back to this management corpus where oversight, approval, escalation, risk acceptance, staffing, or governance boundaries apply.

Governance/advisory guidance lives in [docs-governance-practices](https://github.com/RusDavies/docs-governance-practices), with board-member, advisor, committee/council, sponsor/steward, and governance-template guidance kept out of this management corpus unless the role is explicitly management-scoped.

## Repository Checks

Run the local structural Markdown check before merging navigation-heavy changes:

```bash
scripts/check_markdown_repo.py
```

The checker validates repository-local Markdown links, local assets, heading anchors, and Markdown documents that are not reachable from `README.md` / `DOCUMENT_MAP.md`. External links are not fetched; nobody needs CI to fail because the internet sneezed.
