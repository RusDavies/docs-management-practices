# Compliance Control Register

## Purpose

Record the controls that satisfy compliance obligations, who owns them, how they operate, what evidence they produce, and how failures or exceptions are handled.

## Usage Notes

- Place ownership close to the real work. Compliance can coordinate; it usually cannot know whether a production access role is still appropriate.
- Define failure conditions. If nobody knows what “control failed” means, the control is more decorative than defensive.
- Connect controls to evidence and obligations so audit preparation does not become emergency archaeology.

## Example

A privileged-access review control might map to security and contractual obligations, run quarterly, be owned by system owners, require reviewer signoff evidence, and escalate stale owner mappings before access is approved.
