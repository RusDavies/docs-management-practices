## Feedback From New Joiner

- What was missing?
- What was stale or confusing?
- Which links were useful?
- Which links were noise?
- What should change before the next person joins?

## Usage Notes

- Keep this curated. A link avalanche is not onboarding; it is document-based hazing.
- Update after each new joiner provides feedback.
- Include enough context to prevent repeated explanation, but keep sensitive or restricted content behind proper access controls.

## Example

For a support engineer, include escalation paths, known-issue sources, customer-communication standards, product glossary, support tooling access, runbooks, and a shadowing plan with an experienced engineer.
